# Building Fitness Exporter

An iPhone-only SwiftUI app (iOS 18, Swift 6 with strict concurrency) whose
Xcode project is generated by XcodeGen from `project.yml`. The project is
git-ignored: edit `project.yml`, never the `.xcodeproj`. The `Makefile` wraps
the commands and `CLAUDE.md` lists the everyday ones; this is the fuller
reference.

## Prerequisites

| Tool | Why | Checked here |
|---|---|---|
| Xcode 26, with an iOS simulator runtime that has an iPhone 17 Pro | Builds and tests; `make test` runs on that simulator | Xcode 26.6, iOS 26.5 runtime, Swift 6.3.3 |
| XcodeGen (Homebrew) | `make generate`, which `make build` and `make test` run first | — |
| swift-format (in Xcode's toolchain, as `swift format`) | `make lint`, `make format` | 6.3.0 |
| oxipng (Homebrew) | Only `make icon`; without it the icon is left unoptimised and the Makefile says so | 10.2.1 |

## Commands

| Command | What it does |
|---|---|
| `make generate` | `xcodegen generate --spec project.yml`. Run it after any change to `project.yml`. |
| `make build` | Generates, then builds Debug for a generic iOS device with `CODE_SIGNING_ALLOWED=NO`. About 20 s. The `.app` lands in DerivedData under `Debug-iphoneos`; it is unsigned and carries no entitlements, so it is a compile check, not something to run. |
| `make test` | Generates, then runs the suite on `platform=iOS Simulator,OS=latest,name=iPhone 17 Pro`, unsigned. 46 tests in 11 suites, 0.1–0.3 s of testing; 10–14 s warm, nearly all of it the build and the simulator starting. |
| `make lint` | `swift format lint --strict` over `FitnessExporter/` and `FitnessExporterTests/`. 0.25 s. |
| `make format` | `swift format --in-place` over the same two folders. |
| `make icon` | `swift icon/makeicon.swift` renders the 1024 px icon into `Assets.xcassets/AppIcon.appiconset/icon.png` and a 256 px `icon/preview.png`, then runs `oxipng -o max --zopfli --strip safe` on both. Edit the script, never the PNG. |
| `make clean` | Removes `build/` and runs `xcodebuild clean`, which needs the generated project. |

`DESTINATION` and `SIM_DESTINATION` are make variables, so another simulator is
`make test SIM_DESTINATION="platform=iOS Simulator,OS=latest,name=iPhone 17 Pro Max"`.
If the named simulator doesn't exist, xcodebuild stops with "Unable to find a
device matching the provided destination specifier"; `xcrun simctl list devices available` lists what does.

### One test or one suite

```sh
xcodebuild -scheme FitnessExporter -destination "platform=iOS Simulator,OS=latest,name=iPhone 17 Pro" \
    test CODE_SIGNING_ALLOWED=NO \
    -only-testing:'FitnessExporterTests/FileExporterTests/refusesToOverwriteCorruptExistingFile()'
```

A suite is `-only-testing:FitnessExporterTests/HTTPExporterRequestTests`. Swift Testing
names a test with its parentheses. About 10 s warm; 33 s when it has to
rebuild first. Run `make generate` first if the project isn't there.

### What the suite can and can't reach

The test target compiles the app's sources directly (all of `FitnessExporter/`
except `App/FitnessExporterApp.swift`), with no host app and no
`@testable import`. So the tests run without installing the app, without
HealthKit data and without Keychain access (a real Keychain call fails with
`-34018`, a missing entitlement). They cover the model, the encoder and
decoder, `FileExporter`, `HTTPExporter` (the HTTPS check, and through a stub
`URLProtocol` the request it sends and how it reads a reply),
`KeychainService`'s save logic through fake Security calls, and
`HealthKitService.dataPoints`. `HealthKitService`'s queries, `AppViewModel`,
the real Keychain and the views are checked only in the running app — the simulator, whose runtime ships the Health app for entering
samples by hand, or the user's iPhone. `workflow-checking-work` says what to
report.

### A build to run

A simulator build signed to run locally embeds the HealthKit entitlement (in
the executable's `__entitlements` section); the unsigned `make build` and
`make test` products don't. For a trial:

```sh
xcodebuild -scheme FitnessExporter -destination "platform=iOS Simulator,name=iPhone 17 Pro" build
```

then install and launch it as `workflow-hand-over-for-trial` describes.

### Size

`native-small-bundle` has the Release size (628 KB) and the command that
measures it, into `build/size`.

## What CI runs

`.github/workflows/ci.yml`, on pushes and pull requests to `main`: macOS 26 with
Xcode 26.6 pinned, so its swift-format matches a local Xcode 26.6;
`brew install xcodegen`; `make lint`; `xcodegen generate`; then the
suite on the iPhone 17 Pro simulator, piped through `xcpretty` with `pipefail`
so a failure fails the step. `make lint && make test` is the local equivalent.

## Hooks

- **Git:** `.githooks/pre-commit` runs `make lint` and `make test`, so a commit
  takes 10–15 s. It is on in this clone; a fresh clone needs
  `git config core.hooksPath .githooks`.
- **Claude Code:** `.claude/hooks/swift-format.sh` formats each Swift file as
  it is edited and `.claude/hooks/swift-line-length.sh` then reports any line
  still over `.swift-format`'s 110 columns, with `hook-lib.sh` shared between
  them, once `.claude/settings.json` registers them as `PostToolUse` hooks.
  That file doesn't exist yet. Both are advisory: a missing tool is skipped,
  and only the over-long lines come back.

## Shipping

Run only when the user asks. There is no release script or workflow here;
archiving, signing and uploading happen in Xcode, outside the repo. What the
repo holds for it:

- The scheme archives the Release configuration (`project.yml`).
- Signing is automatic (`CODE_SIGN_STYLE: Automatic`) with no team in the repo;
  the user's own team signs.
- The version is `CFBundleShortVersionString` (1.1.0) and `CFBundleVersion` (1)
  in `project.yml`: change them there, then `make generate`.
- `ITSAppUsesNonExemptEncryption: false` answers App Store Connect's export
  compliance question, so an upload doesn't ask it each time
  (/documentation/bundleresources/information-property-list/itsappusesnonexemptencryption).
- `PRIVACY.md` is the privacy policy, and `screenshots/` holds 1284 × 2778 and
  2778 × 1284 screenshots and a copy of the icon.
